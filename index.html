判定の仕組みと注意

  1. 入力を組織ドメインに正規化（URL・メールアドレス・www を除去）。MX が無ければ上位の組織ドメイン（例: sub.example.co.jp → example.co.jp）でも試します。
  2. MX レコードのホスト名をベンダー署名（ 種）と照合。一致しない場合（Xserver やさくらは MX を自社ドメインに向けるのが標準）は、MX の IP の逆引き（PTR）、SPF の a:sv####.xserver.jp のようなサーバー名、AS 番号（Team Cymru）、ネームサーバーから、レンタルサーバー事業者か、ISP 回線上の自社サーバー（オンプレ）か、IaaS 上の自前サーバーかを推定します。
  3. SPF の include、DKIM セレクタ（google / selector1・2）、autodiscover を見て、ゲートウェイの裏側で使われている基盤（Google Workspace / Microsoft 365 など）を推定します。
高: MX 署名に一致 中: 逆引き / AS から推定 低: 材料不足・ヒューリスティック
限界と読み方
  • MX は「受信の入口」です。ゲートウェイ配下では裏側が読めないことがあり、その場合は △ 要確認 になります。
  • Web サイトのドメインとメールのドメインが違う会社（グループ持株会社など）は判定できません。
  • 自社ドメイン内の MX ＋ ISP 回線の IP は「オンプレ濃厚」ですが、データセンターに預けた自社サーバーの可能性も含みます。
  • DNS の問い合わせは Google / Cloudflare の DNS over HTTPS（またはローカルの Node サーバー）経由で行い、対象のメールサーバーには一切接続しません。
